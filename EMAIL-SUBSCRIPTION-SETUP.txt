TORCH INSIGHTS EMAIL SUBSCRIPTION INTEGRATION

What this package adds
- A branded subscription form to the generated Torch Insights homepage.
- A Netlify Function that validates the form and sends a branded double-opt-in confirmation email directly through Brevo's transactional email API. No Brevo template ID is required.
- A cryptographically random, single-use confirmation token. Only its SHA-256 hash is stored in Netlify Blobs; the token expires after 24 hours.
- A confirmation function that adds the contact to the Brevo subscriber list only after the visitor opens the link and then explicitly clicks the confirmation button on the landing page (so email link scanners do not automatically subscribe them).
- A confirmation landing page at /blog/subscription-confirmed/.
- A local Netlify Build Plugin that detects newly created Markdown articles after a successful Git-based deploy and sends a branded Brevo email campaign to the subscriber list.
- A cached sent-article record to reduce the risk of sending the same article notification again on later deploys.

Brevo list
- Torch Insights Subscribers
- List ID: 3

Netlify environment variables to add
- BREVO_API_KEY: the private Brevo API key. Never put this in a website file or share it in chat. It needs permissions for Contacts, Transactional Email, and Email Campaigns.
- BREVO_LIST_ID: 3
- BREVO_SENDER_EMAIL: info@thetorchacademy.ng (the verified sender address).
- BREVO_SENDER_NAME: The Torch Academy
- BREVO_SITE_URL: https://thetorchacademy.ng (optional; this is the default confirmation-link base URL).

No BREVO_DOI_TEMPLATE_ID or BREVO_DOI_REDIRECT_URL is required. The confirmation message is generated by the Netlify Function and sent using Brevo's transactional email endpoint.

Storage and deployment
- The @netlify/blobs package is used for site-wide storage of pending confirmation records. Netlify provisions access automatically inside deployed Functions.
- Deploy the site through its connected Git repository or Netlify CLI so Netlify Functions and Blobs are available.
- Node.js 18 or newer is required for the Fetch API used by the functions and Netlify Blobs.
- The subscriber list is updated only after a valid, unexpired confirmation token is used.
- Pending token records expire logically after 24 hours; expired records are deleted when their confirmation link is opened.

Article notifications
- The article notification is generated as HTML by the Netlify plugin and sent as a Brevo email campaign. It does not depend on a Marketing template ID.
- The email contains a Brevo unsubscribe link.
- The Netlify site must be deployed from its connected Git repository so the build plugin can identify newly created files in blog/posts/. A drag-and-drop deploy without Git history cannot reliably identify newly published articles.
- The plugin runs after a successful deployment, so article notifications are not sent for drafts or failed deploys.
- Article notifications are sent only for newly created Markdown files; edits to existing articles do not trigger another announcement.

Security
- The API key is read only from Netlify environment variables at runtime/build time.
- No API key or credential is included in public HTML or JavaScript.
- The confirmation token is generated using Node's cryptographic random generator, stored only as a hash, expires after 24 hours, and is deleted after successful use.
- The form requires explicit consent and uses a hidden honeypot field to deter basic bot submissions.
